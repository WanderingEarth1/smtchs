## 三、首次访问需信任证书

因为用的是**自签证书**，浏览器会提示「不安全」。这是正常的，需要手动信任一次：

### Chrome / Edge（电脑）

1. 打开 `https://192.168.2.79:5273/`
2. 看到「您的连接不是私密连接」→ 点「高级」
3. 点「继续前往 192.168.2.79（不安全）」

### Safari（iPhone）

1. 打开地址，提示「此连接非私人连接」
2. 点「显示详细信息」→「访问此网站」
3. 输入手机密码确认

### Chrome（Android）

1. 打开地址，提示「您的连接不是私密连接」
2. 点「高级」→「继续前往」

> 信任一次后，同一浏览器后续访问不再提示。

## 四、为什么必须用 HTTPS

浏览器规定：**GPS 定位只能在安全上下文（HTTPS 或 localhost）下使用**。

用 HTTP 访问时，`navigator.geolocation` 会直接报错：

```
Only secure origins are allowed (see: https://goo.gl/Y0ZkNV).
```

这会导致员工端「新增记录」页的「GPS 定位」按钮失效，记录只能标记为「未获取定位」。

改用 HTTPS 后定位恢复正常，实测可获取到经纬度。

## 六、证书说明

证书位置：`certs/cert.pem`、`certs/key.pem`

- 有效期：1 年（2026-11-11 ~ 2027-11-11）
- 覆盖域名/IP：`localhost`、`smtchs.local`、`127.0.0.1`、`192.168.2.79`、`192.168.2.23`、`44.10.1.37`

### 重新生成（IP 变化时）

```bash
cd certs
# 修改 san.cnf 里的 IP 列表
openssl req -x509 -newkey rsa:2048 -nodes -keyout key.pem -out cert.pem -days 365 -config san.cnf
# 重启两个前端服务
```

## 七、常见问题

### Q: 页面打不开

1. 确认在同一局域网（手机连的 WiFi 要和电脑一致）
2. 确认服务在跑：`lsof -nP -iTCP:5273 -sTCP:LISTEN`
3. 检查防火墙是否拦截

### Q: 登录后一直跳回登录页

清浏览器缓存和 localStorage，重新登录。

### Q: 定位一直失败

1. 确认地址是 `https://` 开头（不是 `http://`）
2. 确认已信任证书
3. 确认浏览器有定位权限（系统设置里）
4. 室内 GPS 信号弱，可到窗边重试

### Q: 管理端登录提示「验证码已失效」

验证码已关闭。若仍提示，清 Redis 缓存：

```bash
cd /tmp/valkey/valkey/9.1.3 && ./bin/valkey-cli -p 6380 FLUSHALL
```

### Q: 数据不显示

检查后端是否在跑，以及 MariaDB / Valkey 是否正常。
