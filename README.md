# 工程师上门服务记录与提成核算系统 · 原型

Vue 3 + Vite + TypeScript 实现的 H5 交互原型，包含**员工端**与**管理端（PC / 移动）**。

---

## 一、快速开始

### 环境要求

- Node.js **≥ 18**（推荐 20 或 22）
- 包管理器：pnpm（推荐）或 npm

### 安装与运行

```bash
# 1. 安装依赖
pnpm install
# 若未安装 pnpm：npm i -g pnpm
# 也可用 npm：npm install

# 2. 启动开发服务器
pnpm dev
```

启动后浏览器打开终端提示的地址，默认是 `http://127.0.0.1:5273/`。

### 其他命令

```bash
pnpm test        # 运行 185 项自动化测试
pnpm build       # 生产构建（含类型检查），产物在 dist/
pnpm preview     # 预览生产构建
```

### 手机访问（同一 WiFi）

```bash
# 查看本机局域网 IP
ipconfig getifaddr en0        # macOS
hostname -I                   # Linux
ipconfig                      # Windows
```

手机浏览器访问 `http://<你的IP>:5273/` 即可。

> 注意：`http` 协议下浏览器会禁用 GPS 定位，记录会标记「未获取定位」（这是需求定义的兜底行为，不影响提交）。要验证定位需部署到 HTTPS。

## 四、功能范围

### 员工端（H5）

- 登录 / 记住登录（30 天）/ 修改密码
- 首页：当月提成汇总、服务地图、最近记录、底部圆形新增按钮
- 新增记录：工作类型、日期时间、地点、GPS 定位、工作内容、照片（1~3 张）、备注
- 实时金额预估（含加班分段说明）
- 我的记录：按月 + 状态筛选，按日期分组
- 记录详情：计费明细、地图定位、修正痕迹
- 待确认/已驳回记录可修改删除，已确认锁定

### 管理端 PC（若依风格，全功能）

- 经营概览：核心指标、待办、提成排行、类型分布
- 记录审核：逐条/批量确认、驳回（原因必填）、修正已确认记录（留痕）
- 月度报表：汇总、按员工/类型统计、下钻明细、**导出 Excel（双 Sheet）**
- 系统配置：员工管理、工作类型、单价矩阵、计费规则

### 管理端移动（只读 + 审核）

- 金额汇总：总额、按员工/类型统计、下钻明细
- 详细记录：按月/状态/员工/关键词筛选，查看详情与地图
- 记录审核：逐条/批量确认、驳回

> 移动端**不含**配置管理与 Excel 导出（按需求约定）。

## 五、计费规则

### 按次计费

```
金额 = 单价（元/次） × 1
```
不参与加班与取整。

### 按小时计费（含加班）

```
T₁ = min(结束, 起算) − 开始        （开始已晚于起算点则 T₁ = 0）
T₂ = 结束 − max(开始, 起算)        （结束早于起算点则 T₂ = 0）
T₁、T₂ 分别按取整规则向上补足
金额 = T₁ × 单价 + T₂ × 单价 × 倍率
```

跨 0 点的连续服务时长归入加班段连续计算。

### 文档示例复现

| 示例 | 场景 | 期望 | 实测 |
|---|---|---|---|
| 1 | 17:30~19:30，80 元/h，精确到分钟 | 280 元 | ✅ |
| 2 | 17:30~19:40，80 元/h，半小时向上 | 360 元 | ✅ |
| 3 | 按次 50 元/次，白天与夜间各一次 | 各 50 元 | ✅ |
| 4 | 送货 12 次 + 维修正常 30h + 加班 6h | 3960 元 | ✅ |

```
├── data/
│   ├── storage.ts     持久层（localStorage）
│   ├── service.ts     业务服务层（规则单点实现）
│   ├── seed.ts        演示数据
│   └── export.ts      Excel 双 Sheet 导出
├── components/        通用组件（图标/弹层/徽标/照片/地图）

│   └── admin-mobile/  管理端移动页面
├── styles/            设计令牌 + 排版系统 + 组件样式
├── stores/            会话 / 主题 / Toast
└── router/            路由 + 角色守卫 + 设备分流
tests/                 185 项自动化测试
```

### 架构要点

1. **计费逻辑与 UI 完全解耦** —— `core/billing.ts` 是纯函数，可在 Node 中直接测试
2. **业务规则单点实现** —— 所有写操作经 `data/service.ts`
3. **计费参数快照** —— 记录提交时固化单价/加班规则/取整规则，配置变更不影响历史核算
4. **持久层可替换** —— `storage.ts` 接口签名与 REST API 一致，迁移后端只需替换实现

### 坐标系说明

浏览器 Geolocation 返回 **WGS-84**（GPS 原始坐标），高德瓦片使用 **GCJ-02**（国测局加密坐标）。直接叠加会偏移 300~600 米，因此绘制前先转换：

```ts
const [gLat, gLng] = wgs84ToGcj02(p.lat, p.lng)
```

## 九、已知限制

| 项 | 说明 |
|---|---|
| 数据存储 | 使用 `localStorage` 模拟后端，数据仅存于当前浏览器；清除浏览器数据会重置为演示数据 |
| 密码摘要 | 使用 Web Crypto SHA-256 + 固定盐；生产环境应改为后端 bcrypt/argon2 |
| 照片存储 | 压缩后以 dataURL 存于 localStorage（约 300KB/张上限） |
| Excel 照片链接 | 原型中照片为内联 dataURL，导出时以「凭证1(5KB)」占位；生产环境应导出真实 URL |
| 定位精度 | 依赖浏览器 Geolocation，微信内置浏览器可能受限 |
| 地图瓦片 | 使用高德公开瓦片，仅用于原型演示；商用需申请正式 Key |

### 生产化建议

1. **后端**：Spring Boot 3 + MySQL 8 单体应用
2. **认证**：JWT + 刷新令牌，服务端校验角色权限
3. **文件**：照片上传至对象存储，记录只存 URL
4. **管理端 PC**：接入若依（RuoYi）框架，替换 `AdminPcLayout.vue` 为若依 `Layout`，页面内容可直接复用
5. **数据留存**：按月归档，定期备份（需求要求至少 3 年）

## 十一、常见问题

**Q：`pnpm install` 报 esbuild 构建脚本被忽略？**

已在 `pnpm-workspace.yaml` 中配置 `onlyBuiltDependencies: [esbuild]`，正常安装即可。若仍报错，执行 `pnpm approve-builds` 选择 esbuild。

**Q：端口 5273 被占用？**

Vite 会自动切换到下一个可用端口，以终端输出为准。也可手动指定：`pnpm dev --port 3000`。

**Q：地图不显示？**

- 检查网络能否访问 `webrd0*.is.autonavi.com`
- 无定位的记录会显示「该记录未获取定位」占位，属正常降级
- `http` 协议下浏览器禁用 GPS，需 HTTPS 或 localhost

**Q：数据乱了想重置？**

浏览器开发者工具 → Application → Local Storage → 删除所有 `smtchs.v1.*` 开头的键，刷新页面即可恢复演示数据。
